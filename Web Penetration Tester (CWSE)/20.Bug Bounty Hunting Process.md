### What is a Bug Bounty Program (BBP)?

A **Bug Bounty Program** is a crowdsourced security initiative where organizations reward security researchers for finding and responsibly reporting vulnerabilities.

It is also known as a **Vulnerability Rewards Program (VRP)**.

BBPs provide **continuous and proactive security testing**, complementing:
- Internal code reviews
- Penetration tests
- Vulnerability management processes

> HackerOne describes this as **“Continuous testing, constant protection”**, integrated into the software development lifecycle.

---
## Types of Bug Bounty Programs

### 1. Private Bug Bounty Programs

- Not publicly accessible
- Invitation-only
- Usually the **starting phase** of most programs
- Invitations based on:
    - Past valid reports
    - Consistency
    - Low violation record
- Some programs may require **background checks**

### 2. Public Bug Bounty Programs

- Open to **everyone**
- Accessible to the entire hacking community
- No invitation required

### 3. Parent / Child Programs

- Used by large organizations
- A **parent company** and its **subsidiaries** share:
    - One bounty pool
    - One security team
- Subsidiary programs are linked to the parent program

---
## BBP vs VDP (Important Difference)

### Vulnerability Disclosure Program (VDP)

- Only explains **how to report vulnerabilities**
- No monetary reward
### Bug Bounty Program (BBP)

- Encourages vulnerability discovery
- Provides **financial rewards**    

These terms **should not be used interchangeably**

## Bug Bounty Program Code of Conduct

- Every program has a **code of conduct**
- Violation history affects:
    - Reputation
    - Invitations to private programs
- Always read:
    - Code of Conduct
    - Program Policy

To succeed, a bug bounty hunter must balance:
- **Professionalism**
- **Technical skills**

---

## Bug Bounty Program Structure (Policy)

A bug bounty program policy explains:

- What you can test
    
- How to report vulnerabilities
    
- What is rewarded
    

On platforms like **HackerOne**, policies usually include:

### Core Components

- **Vendor Response SLAs**  
    Response timelines from the organization
- **Access**  
    How to create test accounts or get access
- **Eligibility Criteria**
    Rules such as “first reporter only”
- **Responsible Disclosure Policy**  
    Disclosure timelines and coordination rules
- **Rules of Engagement**  
    Allowed and forbidden testing behavior
- **Scope**  
    In-scope:
    - Domains
    - IP ranges
    - Applications
    - Vulnerability types
- **Out of Scope**  
    Explicitly forbidden targets or attacks
- **Reporting Format**  
    Required structure for reports
- **Rewards**  
    Bounty amounts and severity mapping
- **Safe Harbor**  
    Legal protection if rules are followed
- **Legal Terms & Conditions**
- **Contact Information**

>Note: Always read the **policy carefully** , Respect scope and rules, Follow responsible disclosure, Avoid violations — reputation matters, Time matters in bug bounty hunting
