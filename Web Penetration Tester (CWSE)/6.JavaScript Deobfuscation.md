**JavaScript deobfuscation** is the process of analyzing and reversing intentionally hidden or scrambled code.

It is an essential skill for:

- Code analysis
- Reverse engineering
- Malware investigation
- Red team and blue team operations

In real-world scenarios and CTF challenges:

- Attackers often use **obfuscated JavaScript** to hide malicious functionality.
- Malware may use obfuscated JS to download or execute its main payload.
- Without deobfuscating the code, it is difficult to understand its true behavior.

#### Why It Matters?

- Helps identify hidden malicious actions.
- Enables deeper understanding of web-based attacks.
- Critical for both:
    - **Red team** (analyzing exploit code)
    - **Blue team** (investigating and defending against attacks)

# Source Code

#### 1. Client-Side Source Code Basics

Modern websites use three main technologies:

- **HTML** → Defines structure (content, fields, layout)
- **CSS** → Defines styling (design, fonts, spacing)
- **JavaScript (JS)** → Handles functionality and logic

Even though this code runs in the browser, it is fully available to the client.

#### 2. Viewing HTML Source

- You can view page source using **CTRL + U**.
- This reveals:
    - HTML structure
    - Embedded CSS
    - JavaScript references
    - Developer comments

### Why Check HTML?

- Developers may leave:
    - Comments with hints
    - Hidden inputs
    - Sensitive information
- Always read HTML comments carefully during CTF.

#### 3. CSS

CSS can be:

✔ Internal CSS

```
<style>
h1 { font-size: 144px; }
p { font-size: 64px; }
</style>
```

✔ External CSS

```
<link rel="stylesheet" href="style.css">
```

✔ Inline CSS (directly on element)

```
<h1 style="color: red;">Hello</h1>
```

#### 4. JavaScript

JavaScript can also be:

✔ Internal JS

```
<script>
    // JS code here
</script>
```

✔ External JS

```
<script src="secret.js"></script>
```

✔ Inline JavaScript (inside element attributes)

```
<button onclick="alert('Clicked!')">Click Me</button>
```

#### 5. Obfuscated JavaScript

When opening `secret.js`, you see something like:

```
eval(function(p,a,c,k,e,d){...})
```

# Code Obfuscation

Before we start learning about `deobfuscation`, we must first learn about `code obfuscation`. Without understanding how code is obfuscated, we may not be able to successfully deobfuscate the code, especially if it was obfuscated using a custom obfuscator.

**Code obfuscation** is a technique used to make code:

- Hard for humans to read
- Difficult to reverse engineer
- But still fully functional for the machine

Important:

- Functionality stays the same
- Performance may slightly decrease
- Done automatically using obfuscation tools

#### 1. How Obfuscation Works

Obfuscators transform code by:

- Renaming variables to meaningless names
- Encoding strings
- Changing control flow
- Wrapping logic in decoding functions
- Using string dictionaries

Example Concept:

Instead of:

```
console.log("Hello");
```

It may become:

```
eval(function(p,a,c,k,e,d){e=function(c){return c};if(!''.replace(/^/,String)){while(c--){d[c]=k[c]||c}k=[function(e){return d[e]}];e=function(){return'\\w+'};c=1};while(c--){if(k[c]){p=p.replace(new RegExp('\\b'+e(c)+'\\b','g'),k[c])}}return p}('0.1("2 3");',4,4,'console|log|hello|world'.split('|'),0,{}))
```

Or even more complex with runtime decryption.

#### 2. Why JavaScript is Commonly Obfuscated

Languages like:

- Python
- PHP

→ Usually run server-side  
→ Not visible to users

But:

JavaScript runs:

- Client-side (browser)
- Sent in cleartext to users

Because of this:

- Anyone can view source
- Anyone can inspect logic
- Anyone can copy code

So developers use obfuscation to hide logic.

#### 3. Use Cases of Obfuscation

Protect Intellectual Property:

- Prevent copying code
- Hide business logic
- Make reverse engineering harder

Add a Security Layer:

- Hide authentication logic
- Hide encryption routines

⚠ Important:  
Client-side authentication/encryption is NOT secure.  
Users can still:

- Read
- Modify
- Bypass it

Never trust client-side logic in real-world apps.

Malicious Usage (Most Common in Pentesting):

Attackers use obfuscation to:

- Bypass IDS/IPS systems
- Hide malicious payloads
- Evade antivirus detection
- Avoid signature-based detection

Common in:

- Malicious JavaScript
- Phishing pages
- Drive-by downloads
- Exploit kits
